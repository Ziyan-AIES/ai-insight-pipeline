# Signal Reference 综合提炼与来源覆盖修复

## 已核实的问题

1. 旧摘要虽然读取一批文章，但提示词允许挑选单篇新闻，且只取最新 250 条；实际旧日报三卡分别只有一个引用，没有达到跨新闻归纳的要求。
2. 采集时先要求命中具体词典，未命中的原始文章直接丢弃。RSS 解析又优先读取短导语，而非可用正文，进一步漏掉 Investor 的研究内容。
3. 页面只显示至少两个独立事件组成的话题，没有展示原始采集列表；因此单篇内容和未命中词典的内容都不可见。
4. Lightspeed 的真实邮件地址为 `lsvp@mail.beehiiv.com`，旧的出版社域名匹配无法识别。现只授权该完整地址对应已登记的 Lightspeed Newsletter，不泛化整个邮件平台。
5. RSS 重复刷新会覆盖旧条目的 discovery 时间，可能把旧文重新算成当日发现；改为保留首次发现时间。

## 修复后的生成逻辑

周期内成功采集的 RSS、API、网站及已核实邮件内容 → 每篇提取事实与明确排除原因 → 按主题汇总全部提取结果 → 跨公司、跨事件归纳最多三张卡片。各步分批处理，不截掉第 251 篇及之后的文章。重复报道也读取，但不当作多个独立事件。

最终每张卡至少引用两个独立事件，描述共同变化、差异或约束；单条苹果新闻不能独立构成一个 takeaway。没有足够证据时允许少于三张。投资人观点保留观点属性，发布与可用、预测与实际采用分开。界面显示审阅数量和覆盖限制；可用 RSS 摘录不冒充完整网页阅读。

原始文章保存在现有 radar_items，即使没有词典标签也进入摘要输入，并能在对应来源筛选下展开查看。关键词话题排名仍使用原有规则，未调整权重。历史日期保持原样，邮件中推荐旧文不会被改成新文日期。
